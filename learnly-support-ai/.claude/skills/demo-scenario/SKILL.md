# Демо-сценарій (2–3 хв, відео вшивається в презентацію)

## Підготовка
```bash
uvicorn app.main:app            # або запустіть задеплоєний URL
# у UI натисни «Reset demo» → чистий стан з сід-даними
```
Для запису екрана — вікно браузера 1440×900, зум 100%, закрити зайві вкладки. Записувати кілька дублів, залишити найкращий.

## Сценарій «Врятований учень» (головний)
1. **Контекст (10 с).** Learnly — онлайн-школа, 4 курси. Показати інбокс з пріоритетами P1/P2/P3.
2. **Нове звернення.** Олена (Python, оплата 5 днів тому) пише: «Хочу повернути гроші за курс».
3. **AI-аналіз у правій панелі (30 с).** Намір = повернення; *справжня мета* = «потрібно більше часу» (9/12 уроків за планом, відставання 3); churn-risk; блок *reasoning* з числами.
4. **Дія.** AI рекомендує `transfer_cohort → PY-NOV` замість повернення 9 900 грн; запасний варіант — повернення. Агент натискає **Approve** (1 клік).
5. **Результат.** Стан учня змінився, чат отримав підтвердження, тікет закрито як «врятований». Перейти на **Dashboard**: +1 врятований учень, збережено 9 900 грн.

## Другий сценарій «Подвійне списання» (30 с)
Ірина (злюча): AI ставить P1, знаходить дубль платежу, пропонує `refund_duplicate_charge` (high risk → потребує approve).

## Третій «Якість підтримки» (30 с)
Агент пише грубу відповідь → показати оцінку якості та поради. Потім надіслати AI-чернетку → вища оцінка.

## Четвертий (бонус) «Автономність»
Перемкнути в `auto_low_risk` → створити звернення про доступ (Максим): `grant_access` виконується сам, high-risk дії все одно чекають людину.

## План Б
- Немає інтернету/ключа → працює fallback (`source: rules`) — демо ідентичне.
- Падає UI → заздалегідь записане відео + curl-приклади з `README.md`.

## Що сказати журі (по критеріях)
- *Operational impact:* автодії + менше ручних кроків, врятовані учні в грошах.
- *Use of AI:* LLM розуміє намір і мету, tool calling, оцінка якості.
- *Reasoning & Context:* показуємо reasoning з числами контексту.
- *Technical:* policy-guard поза LLM, audit log, тести, fallback.
