# Додати нову дію AI (tool)

Усі дії живуть у `app/tools.py`. LLM лише *пропонує* дію, виконує і перевіряє її код.

## Кроки
1. **Правило.** Запиши бізнес-правило в `app/policy.py` (константа) і в `docs/features/ai-support-copilot/business-context.md`.
2. **Ризик:** `low` (оборотне, без грошей) · `medium` (змінює навчання/ескалація) · `high` (гроші). `medium/high` → завжди потребують approve.
3. **Реалізуй пару функцій** у `tools.py`:
   - `_chk_<name>(student, args)` — кидає `PolicyError("зрозуміле повідомлення")`, якщо не можна.
   - `_run_<name>(student, args)` — змінює стан учня, повертає `{"summary": "..."}` (і додаткові поля, напр. `amount`).
4. **Зареєструй** у словнику `TOOLS` (`Tool(name, risk, title, description, check, run, args_hint)`).
5. **Навчи агента:** у `agent.py` додай, коли tool рекомендується (`heuristic_analyze`) — і переконайся, що каталог tools для LLM підтягується автоматично з `TOOLS`.
6. **Тести (спершу!):** у `tests/test_tools.py` — щасливий шлях + щонайменше 2 порушення політики. У `tests/test_agent.py` — що агент пропонує tool в потрібному кейсі.
7. **Фронтенд:** нічого не треба, якщо tool має `title` — картка дії рендериться з реєстру. Для спеціального відображення аргументів — `renderArgs()` у `static/index.html`.
8. **Документація:** `entry-points.json`, `business-context.md`, `known-gotchas.md` (див. skill `feature-docs`).

## Чекліст безпеки
- [ ] Перевірка політики в `check()`, а не в промпті
- [ ] Не можна виконати двічі (ідемпотентність або явна помилка)
- [ ] Аргументи приводяться до типів (`int`, `str`), невідомі ключі ігноруються
- [ ] Результат записується в audit log (робить `store`, не tool)
