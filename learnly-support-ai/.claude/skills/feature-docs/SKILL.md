# Документація як контекст для AI

AI пише код так, як описано в документації. Тому `docs/features/<фіча>/` має бути актуальною.

## 10 файлів
| Група | Файл | Що містить |
|---|---|---|
| Що і навіщо | `FEATURE.md` | головний опис фічі |
| | `business-context.md` | бізнес-правила, політики, цифри |
| | `end-to-end-flow.md` | флоу крок за кроком |
| Де в коді | `entry-points.json` | точки входу (endpoints, функції) |
| | `per-app-responsibility.md` | що робить кожен модуль |
| | `backend-structure.md` | структура бекенду |
| | `frontend-structure.md` | структура фронтенду |
| | `data-model.md` | моделі даних |
| Зв'язки і ризики | `integration-points.md` | перетини з іншими системами |
| | `known-gotchas.md` | відомі підводні камені |

## Робочий процес
1. Змінив код → перевір, які файли застаріли (`git diff --stat`).
2. Оновлюй мінімально: тільки те, що змінилось. Не переписуй усе.
3. `entry-points.json` має відповідати реальним роутам у `app/main.py` — перевір `grep -n "@app\." app/main.py`.
4. Якщо в коді логіка не та, що в `business-context.md` — **спершу з'ясуй, що правильно** (це бізнес-питання), а не підлаштовуй документ під код.
5. Нове обмеження чи баг, який ти зловив → одразу в `known-gotchas.md`.

## Формат
Короткі речення, таблиці, жодної води. Мова — українська, терміни коду — англійською.
