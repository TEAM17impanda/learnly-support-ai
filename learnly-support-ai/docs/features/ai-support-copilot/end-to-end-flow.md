# End-to-end флоу: «Врятований учень»

1. Учень (Олена, Python, оплата 5 днів тому, 9/12 уроків за планом) пише: «Хочу повернути гроші за курс».
2. `POST /api/tickets` → `agent.analyze()`:
   - з ключем: LLM → JSON → кожна дія проходить `tools.check()`; без ключа або при збої: `heuristic_analyze()`.
   - intent = `refund`; pace_ratio = 0.75 → true_goal = `needs_more_time`.
3. Створюються дії: `transfer_cohort → PY-NOV` (рекомендована, medium), `extend_deadline` (альтернатива), `request_refund` (запасна, high).
4. Режим `copilot`: усі дії у статусі `proposed`. Режим `auto_low_risk`: рекомендовані `low` виконуються самі.
5. Агент у UI бачить намір, мету, ризик відтоку, **reasoning з числами**, чернетку відповіді.
6. Агент натискає «Підтвердити» → `POST .../actions/{id}/approve` → `tools.execute()`:
   - `check()` перевіряє політику ще раз (стан міг змінитись) → при порушенні дія `failed`, стан не змінюється.
   - `run()` змінює учня; у чат додається системне повідомлення; тікет → `resolved`.
7. Агент надсилає відповідь (можна взяти AI-чернетку) → `quality.score_reply()` → оцінка в чаті.
8. Дашборд: +1 врятований учень, +9 900 грн збережено, економія часу, якість відповідей.

## Альтернативні гілки
- Поза вікном 14 днів → `request_refund` не пропонується, лише ескалація в billing.
- Подвійне списання → `refund_duplicate_charge`, P1.
- Нове повідомлення учня в тікеті → повторний аналіз.
- Невизначений намір → уточнююче питання, жодних дій без підтвердження суті.
