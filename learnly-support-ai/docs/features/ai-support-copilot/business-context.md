# Бізнес-контекст і правила

Єдине джерело правди в коді: `app/policy.py`. Якщо змінюєте правило — міняйте тут і там.

## Політика школи
| Правило | Значення |
|---|---|
| Вікно повернення | 14 днів з оплати |
| Розмір повернення | 100%, якщо пройдено ≤ 30% курсу; інакше 50% |
| Продовження дедлайну | 1–7 днів за раз, максимум 2 рази |
| Перенос на інший потік | 1 раз, якщо пройдено ≤ 50% курсу, тільки в межах того ж курсу |
| Подвійне списання | Повертається різниця повністю, без вікна |
| Відновлення доступу | Якщо є успішна оплата і курс не повернено |
| Сертифікат | Лише після всіх пройдених уроків |
| Ментор-сесії | До 2 безкоштовних |

## Ризик дій
- `low` — оборотні, без грошей: `extend_deadline`, `grant_access`, `book_mentor_session`, `issue_certificate`
- `medium` — змінюють навчання/ескалація: `transfer_cohort`, `escalate_to_human`
- `high` — гроші: `request_refund`, `refund_duplicate_charge`
- `medium` і `high` **завжди** потребують підтвердження людини.

## Логіка «справжньої мети» (повернення)
`pace_ratio = lessons_done / lessons_expected`
- `pace_ratio ≥ 0.6` або текст «не встигаю/немає часу» → **needs_more_time** → пропонуємо перенос/продовження; повернення — запасний варіант.
- Інакше → **disengaged_or_mismatch** → повернення (у вікні) + альтернатива ментор-сесія; поза вікном → ескалація людині.
- Явне «курс не підходить» (mismatch) не вважається нестачею часу, навіть при хорошому темпі.

## Формули
- Пріоритет = база за наміром (double_charge 70, access 65, refund 60, deadline 40, transfer 35, other 30, certificate 25) + 20 якщо роздратований + 10 якщо churn ≥ 60 + 5 якщо ≥ 2 попередніх звернень. P1 ≥ 80, P2 ≥ 55, інакше P3.
- «Врятований учень» = звернення з наміром `refund`, де виконано дію утримання (`transfer_cohort`/`extend_deadline`/`book_mentor_session`) і НЕ виконано `request_refund`.
- Економія часу — модельна: 4 хв за виконану дію + 2 хв за підготовлену чернетку.
