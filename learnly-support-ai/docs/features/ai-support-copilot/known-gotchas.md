# Відомі підводні камені

1. **LLM не вирішує, чи можна дію.** Це робить `tools.check()`. Навіть якщо LLM «переконаний», дія може бути заблокована.
2. **Стан міг змінитись між пропозицією та підтвердженням** → `approve` повторно виконує `check()`; тест `test_policy_guard_blocks_stale_action`.
3. **Повторне підтвердження** дії → HTTP 409.
4. **Порядок патернів інтентів важливий:** `double_charge` перевіряється раніше за `refund`, бо «списали двічі… верніть гроші» — це білінг, а не повернення за курс.
5. **Rule-based інтенти — ключові слова.** Це fallback, а не NLU; LLM-шлях покриває складні формулювання.
6. **Дати рахуються відносно «сьогодні»** (`_d(days_ago)`), тому сценарії стабільні в будь-який день, але `COHORTS` фіксуються на старті процесу.
7. **Перенос потоку обнуляє `lessons_expected`** (новий потік — новий план). Це спрощення MVP.
8. **Час «економії» — модельна оцінка**, не вимірювання. Так і подавати на презентації.
9. **`STATE` глобальний** — один процес, без паралельних користувачів. Для демо достатньо.
10. **`auto_low_risk` виконує лише рекомендовані low-risk дії**; `medium/high` завжди чекають людину.
11. Без `static/index.html` корінь `/` дає 500 — файл обов'язковий.
